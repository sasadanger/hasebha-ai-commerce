# Phase 2C Risk Register (planning only)

Extends `docs/risk_register.md` with Phase 2C-specific risks. No human owner name is invented where none exists in the repository; owner fields name a role/evidence type, not a person.

| Risk | Severity | Likelihood | Impact | Mitigation | Gate affected | Evidence/owner required |
|---|---|---|---|---|---|---|
| AS-OF uncertainty (15 Expanded features remain unproven) | High | Confirmed (current state) | Blocks any Expanded-feature production claim; root cause of the entire Phase 2B `INCONCLUSIVE` outcome | Source-system/documentation AS-OF audit (Phase 2C primary objective) before any reuse | AS-OF gate | Source-system owner evidence per feature |
| NLP leakage (text used after outcome, or text-derived statistics fit outside training fold) | High | Would be realized immediately if the Olist review table were ever used as a feature | Invalid model, repeat of a Phase-2B-class evidence defect but worse (structural leakage, not mislabeling) | Structural prohibition already encoded in `docs/olist_asof_feature_contract.md`; enforce in any future NLP pipeline | Leakage gate | Code review before any NLP execution |
| Egyptian-data absence | High | Confirmed (current state) | No Egyptian-market claim is possible at all | Explicit deferral; evidence-requirements document (`docs/phase2c_egyptian_market_evidence_requirements.md`) | Egypt gate | Egyptian data acquisition (not started) |
| Dataset shift (Olist 2016-2018 Brazil vs. any future deployment market) | High | Certain if Olist-trained parameters are ever reused unchanged | Overstated performance claim outside the source market | Explicit boundary statement; no cross-market inference permitted | Egypt gate, Science gate | External validation data |
| Class imbalance (≈8.1% late-delivery prevalence in Olist) | Medium | Already observed | Could bias threshold/metric choice if not handled explicitly | AP/ROC-AUC/Brier already used instead of accuracy; must carry forward | Science gate | None additional; already mitigated in Phase 2A/2B methodology |
| Calibration failure | Medium | Unknown until measured | A miscalibrated score could mislead a "risk level" business action | Explicit calibration requirement before any threshold work (`configs/olist_phase2c_evaluation.yaml`) | Business gate | Calibration report, not yet produced |
| Text coverage (missing review title/message rates) | Medium | Confirmed for both Olist (58-88% null) and Amazon Appliances (per readiness docs) | Could make an NLP feature unusable or biased toward orders/products with reviews | Coverage measurement required before any NLP feature is approved | NLP gate | Coverage report, not yet produced |
| Arabic dialect robustness | High | Unknown; no Arabic data exists | An NLP model tuned on English Amazon reviews could fail silently on Egyptian Arabic | No Arabic evaluation is claimed until Arabic data exists | NLP gate, Egypt gate | Egyptian/Arabic evaluation set |
| Code-switching (Arabic/English mixed text) | Medium | Unknown; no representative data exists | Same as above, specific to mixed-language input common in Egyptian digital communication | Same as above | NLP gate, Egypt gate | Egyptian/Arabic evaluation set |
| Privacy / data governance | High | Applies to both Amazon review text and any future Egyptian customer data | Legal/compliance exposure; matches `docs/risk_register.md` privacy row | Access minimization, consent verification, license confirmation before use | Egypt gate, NLP gate | Legal/compliance review (license status currently "Not verified" for both Amazon Appliances and Instacart) |
| Data provenance (Instacart and Amazon Appliances license/version "Not verified") | High | Confirmed (current state, `docs/modeling_readiness_gate.md`) | Cannot lawfully use either dataset for modeling until resolved | Provenance/license verification remains outside Phase 2C's Olist-focused scope | Documentation gate | Legal/licensing review (unresolved, pre-existing) |
| Residual Phase 2B generator debt (`PHASE2B_ASOF_LABEL_GENERATOR_DEBT`) | Medium | Realized only if `src/modeling/olist/phase2b_sensitivity.py::development()` is reused without repair | Could regenerate a scientifically invalid `SUPPORTED_INCREMENTAL_SIGNAL` label | Fix required before any Phase 2C evidence-regenerating pipeline use (see `PHASE2C_AUTHORIZATION_RECORD.md` Step 4 decision) | Reproducibility gate, Science gate | Code fix (not performed by this gate) |
| Protected-Test misuse | Critical | Low if governance is followed; catastrophic if not | Would silently invalidate the entire Phase 2A/2B evidence chain and require full re-review | Explicit protected-Test policy (`docs/olist_phase2c_protocol.md`); `access_count` monitoring | Protection gate | Independent review before any future Test access |
| Feature backfill/revision risk (source systems silently changing historical values) | Medium | Unknown; part of what the AS-OF audit must determine | Could make a feature look AS-OF-safe in a snapshot when it is not | Explicit backfill/revision-behavior field required in the feature-eligibility audit (`docs/olist_phase2c_protocol.md`) | AS-OF gate | Source-system documentation, not yet collected |
| Reproducibility risk | Medium | Low given existing discipline (`reproduce()` stage, hash manifests) | Loss of trust in any Phase 2C evidence if not maintained | Continue existing hash/manifest/seed discipline | Reproducibility gate | None additional; already mitigated |
| Overfitting to Olist (methodology tuned to one market's quirks) | Medium | Plausible over time without discipline | Findings that don't generalize even within a future non-Egyptian market | Keep Olist explicitly labeled `DEVELOPMENT_BENCHMARK`; require external validation before any transfer claim | Egypt gate, Science gate | External validation data |
| Business-metric mismatch (optimizing AP/ROC-AUC with no operational interpretation) | Medium | Realized if thresholds are set without business input | Statistically good model that doesn't serve the actual operational decision | Business-value evaluation explicitly deferred pending stakeholder cost input (`configs/olist_phase2c_evaluation.yaml`) | Business gate | Business-owner cost input, not yet available |

No item in this register is resolved by creating the register itself. Each remains open until its "Evidence/owner required" column is satisfied.
